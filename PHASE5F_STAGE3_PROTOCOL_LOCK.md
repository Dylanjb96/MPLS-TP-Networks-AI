# Phase 5F Stage 3 — Development Protocol and Scope Freeze

**Research question:** Can a size-invariant candidate-aware neural policy learn a useful greedy-guided protected-route decision rule across distinct synthetic topologies and static/dynamic services? The Stage 3 milestone is **engineering feasibility**, not definitive comparative performance.

The fixed Stage 2 generator uses different topology structures by seed and up to six deterministic end-to-end link-disjoint working/backup pairs. The unchanged single-physical-link-failure scenario ledger verifies capacity/reservation feasibility for each provisioned LSP. This is not MPLS-TP MSRP; protection-model approval is false.

**Model:** Candidate-shared MLP scoring all currently feasible route pairs; masked categorical policy and centralized state-value estimate. Features: working/backup length and hops, capacity-footprint, bottleneck scenario slack and utilization, normalized capacities, candidate index, greedy-default indicator, current service priority and bandwidth, active-service count, network size, time index, static/dynamic indicator and observed peak reservation utilization. No future arrivals, service suffix, or oracle route rewards enter online decision states. PPO uses full-episode terminal-normalized cumulative priority-weighted admission as its learning objective, optional greedy behaviour cloning, and an evaluation-only default-greedy score-margin gate. Every feasible current request must be admitted.

**Factorial research plan to retain for Stage 4/5:** network size 60 versus 500, K=2 versus K=6, static versus dynamic reservations, and loads 1.6/2.5/4.0; examine interactions and label comparisons as within-condition. 150/250 nodes remain engineering/generalization development pilots. Primary proposed national-scale condition: 500 nodes, six candidate pairs, dynamic service holding, load 4.0. Load change from earlier 1.6/3.2/4.8 was documented from *development-only* calibration before learner evaluation.

**Distinct data partitions (not to be overlapped):** training topologies 201–220, training streams 71000–71007; validation topologies 301–310, validation streams 72000–72002; reserved unseen final topologies 401–420, final demand streams 73000–73002. These are **proposed** frozen partitions and must be checked against any other experimental source usage before full training. Stage 3 CLI enforces only train and validation subsets.

**Minimum comparisons before any conclusion:** greedy, footprint, random-feasible, hybrid; ablations with/without greedy reference signal and with/without enhanced congestion features; several agent initializations; matched topology/demand streams and seed-level paired uncertainty. Do not tune on final test. Final benchmarking must include inference overhead, admission, protection/capacity violations, decision differences, and generalization across previously unseen topologies. Stage 3 does not yet implement all of these Stage 4/5 requirements.
